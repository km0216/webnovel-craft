# 00 · 为什么这么做

## 1. 长篇不是「写不出来」，是「写到一半记不住」

前几章惊艳，第十章还行，第二十章开始不对：人设漂移、伏笔没人收、自己立的规矩被自己打破、同一个场景反复描写。

第一反应是换更贵的模型、把设定贴得更满、把前文全塞进去。收效有限。

**因为问题不在模型，也不在窗口长度，在前提**：你在让它靠记忆写作，而它没有记忆。

上下文是**工作记忆**，不是长期记忆。清一次，被清掉的东西不是变成「印象」，是真没了。人写第 300 章靠的是笔记和大纲，不是脑子——我们给 AI 用的时候却指望它硬扛。

## 2. 社区收敛出的四条

看 Oh Story、天命、小说锻炉、inkos、webnovel-writer、FictionOps、dsh-story 这些项目，术语各异，做法是同一件事的四个面：

1. **状态外置** —— 人物、地点、时间线、伏笔、道具、承诺、认知，全落成结构化字段
2. **每章回写** —— 写完不是结束，是把本章变化写回去；缺这一步，前三条全废
3. **按需注入** —— 下一章只读它真正要用的切片
4. **门禁拦截** —— 写完先过检查，不通过不落地

## 3. 三个视角要分开记

连载里最像「人设崩了」的 bug，八成不是设定矛盾，而是**角色知道了本不该知道的事**。

所以真相要记三份：

- 作者认定的真相（幕后黑手是谁）
- 每个角色此刻能依据的知识（他以为是谁，包括**他错信的事**）
- 读者已经被展示过的（读者知道多少）

三者的错位就是戏剧性：读者知道而角色不知道 = 悬念；角色错信 = 反转；作者知道而读者不知道 = 伏笔。

## 4. 为什么要用代码守纪律

凡是「靠模型自觉」的约束都会失效——它每章都在重新理解你的规则。

- 「不许写死角色复活」写进 prompt → 第 80 章它忘了
- 「伏笔 20 章内要回收」写进 prompt → 它连有哪些伏笔都不记得
- 「字数 2000–3000」写进 prompt → 它给你 1800 或 4500

**能让代码判的，就不交给它判。** 这不是不信任 AI，是不给漂移留口子。

## 5. 这套东西能保证什么

| 能 | 不能 |
|---|---|
| 设定不矛盾 | 好看 |
| 伏笔不丢、到期提醒 | 爽点不俗 |
| 时间线不错乱 | 语感像人 |
| 人物不换人格 | 有梗、有网感 |
| 角色不提前知道结局 | 情绪曲线动人 |

**工程管下限，上限是作者的事。** 反过来说也成立：连下限都不稳的书，再好的构思也会被读者当成乱写。

## 6. 为什么去 AI 味不能靠删词表

因为一半的「AI 味清单」是错的（见 `05` 的永不改表）。按那些改，会把人的正常写法删掉，越改越空。

真正的判据只有两类：**有倍率的**，和**能指出触发标记的**。其余都是审美偏好。

## 7. 一句话

**人定骨架，代码守纪律，AI 只填细节。**
