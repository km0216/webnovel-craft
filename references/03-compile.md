# 03 · 上下文编译

> 写手只该看见「这一章要用的东西」，不是全书。
> 塞得越多，模型越会把「平均」写出来——细节被抹平，约束被稀释，最后连禁区都不记得。

实现：`node scripts/rebuild.js --book DIR --ch N [--max-kb 8]`

## 1. 七个切片（对应 `context.md` 的七栏）

| 切片 | 来源 | 过滤 |
|---|---|---|
| 当前位置 | `ledger/chapter-log.jsonl` + 合同存在性 | 只取上一章 |
| 长期约束 | `book.json.sacred` | 预算再紧也留 ≥6 条 |
| 核心角色 | `canon/characters/*.json` | 主角优先；`known` 只取 ≤ 当前章 |
| 活跃伏笔 | `ledger/foreshadow.jsonl` | 只取未回收；逾期置顶 |
| 近章速记 | `chapter-log` | 最近 3 章 |
| 下一章承诺 | 上一章的合同 | 只取 `next_chapter_commitments` |
| 连贯性风险 | 各种计算结果 | 逾期、缺正文、主角缺席 |

## 2. 事实的三重过滤

只有同时满足三条才进上下文：

1. `canon_status === 'canon'`（待确认/推翻/弃案/推断都不进）
2. `valid_from_ch ≤ N ≤ valid_until_ch`（时间闸）
3. `visible_from_volume ≤ 当前卷`（**剧透闸**）

剧透闸是入闸：还没到公开的卷，事实根本不出现在 prompt 里。
出闸靠 `output_check.js`：正文不许把还没到卷的答案写出来（批 4 可加词面扫描）。

## 3. 预算

默认 8 KB。超了按顺序降级（`rebuild.js` 里的 `ladder`）：

1. 去掉证据片段
2. 长期约束压到 20 条 → 12 → 10 → 6
3. 角色 40 → 20 → 12 → 8 人；`known` 99 → 9 → 5 → 3 条
4. 事实 999 → 60 → 30 → 15 条
5. 承诺 99 → 12 → 8 → 5 条

**永远不砍**：禁区（`forbidden_zones`）、活跃伏笔、逾期告警。砍了正好砍掉最该看的。

## 4. 指令与正文必须分开

```
[上下文]   事实、角色、伏笔、承诺       ← 状态
[合同]     目标、必覆盖节点、禁区       ← 约束
[正文]     已写章节                     ← 素材
```

三者分别成块，不许混在一段散文里。混在一起，模型会把「约束」当「素材」抄进正文——这是 prompt 泄漏的第一原因。

## 5. trace：编译要能审计

每次编译落 `.craft/trace-chNNN.json`：

```json
{ "chapter": 13, "budget_kb": 8, "used_kb": 5.2,
  "facts_injected": ["F4", "F7"], "facts_withheld": ["F9"],
  "foreshadow": ["X1"], "ladder_step": 1, "warnings": [] }
```

问「为什么这章没提到某某设定」时，先看 trace：是被时间闸挡了、被剧透闸挡了、还是被预算砍了。三种原因，处理方式完全不同。

## 6. 常见错

| 错 | 后果 | 改法 |
|---|---|---|
| 把全书正文塞进去 | 模型开始「平均」写作，细节全平 | 只给速记，要细节时定点查 |
| 把评审意见塞进上下文 | 锚定，写完就往评审偏好上靠 | 评审意见只在改稿轮用 |
| 上下文里放「你应该注意」 | 指令混进素材，被抄进正文 | 指令放合同/系统层，不放上下文 |
| 手动编辑 context.md | 下次 rebuild 覆盖，白改 | 改账本，再 rebuild |
| 预算砍到禁区不见了 | 写出来的东西直接撞红线 | 禁区永不砍 |
| 每章重新灌一遍文风样本 | token 烧光且权重反被稀释 | 文风样本只给一段（300–500 字） |

## 7. 一天里的两次编译

| 时机 | 目的 | 看什么 |
|---|---|---|
| 写前 | 给写手最小上下文 | `context.md` 七栏 |
| 写后（结算完） | 为下一章准备，同时看风险 | 风险栏 + trace |

两次都跑 `rebuild`，别自己拼 prompt。
